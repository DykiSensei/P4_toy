# 小小探索家 · 整体 UI 设计草案

版本：v0.2，2026-11-09。状态：**用户已确认“自然手帐”，并授权先实现首页、页面切换与烧录验证**。

依据：[项目整体大纲](../PROJECT_OUTLINE.md)。初稿阶段仅提供交互设计；用户确认后，已进入首页和页面切换的实机验证。实现范围见 [UI_IMPLEMENTATION.md](UI_IMPLEMENTATION.md)，其余业务流程仍为设计目标。

## 1. 设计方向

产品暂用名“小小探索家”，面向 6–12 岁。主线为拍照发现、确认收藏、地图留痕、伙伴对战。

| 方案 | 首页结构 | 气质与用途 |
| --- | --- | --- |
| 自然手帐（主推） | 一个突出拍照的大入口，下方地图／图鉴／对战，底部继续探索 | 暖白、深绿、陶橙；强调观察与自然收集 |
| 冒险面板（备选） | 四个同等大的入口，底部当前探索 | 更规整的四宫格，蓝绿色；减少入口优先级差异 |

两方案使用相同功能结构与状态规则。预览可切换页面，也可直接点击屏幕内按钮。电量、时间、收藏数、识别结果、对战数值、位置和轨迹均为演示数据；植物画面是示意插画，不是摄像头实拍。科普和物种名单尚待内容方案确定。

## 2. 屏幕与视觉规格

- 320×480 竖屏，按实际像素设计；状态栏 28 px，二级页标题栏 48 px。
- 内容边距 14 px；主要间距 8／10／12／16 px。保持一屏一个主要任务。
- 主标题 24–26 px；页面标题 20–22 px；主要按钮 17–18 px；一般信息 16–18 px；辅助文字 13–14 px。地图署名等元信息可更小，不承载操作。
- 主操作高至少 48 px；拍照按钮 68 px；图标按钮 44×44 px。可点击图标配文字或明确名称。
- 主推浅色：背景 `#F8F5EB`、文字 `#203D31`、主绿 `#205D45`、拍照橙 `#B64D25`、辅助面 `#E4EBDB`。圆角以 16 px 为主。
- 预览跟随宿主明暗主题，便于检查对比度；实机首版优先浅色户外阅读，不预先承诺加入主题切换。
- 无持续闪烁、循环装饰动画；反馈优先用文字、图形和明确状态。地图和拍照不依赖高帧率才能理解。

## 3. 页面结构

首页保留四个功能入口；设置位于右上角。二级页左上返回，页面底部放主操作。探索记录属于地图，观察记录属于图鉴；不额外挤入五栏底部导航。

| 功能 | 页面与主要动作 |
| --- | --- |
| 拍照发现 | 取景 → 照片确认／重拍 → 识别中 → 候选确认 → 收藏成功；可先存照片 |
| 我的图鉴 | 已收藏／待确认；物种详情分“认识它、发现记录、对战卡”；空图鉴引导拍照 |
| 探索地图 | 准备开始、记录中、暂停、继续、结束确认、保存完成；缩放、回到位置、拍照入口 |
| 探索记录 | 历史列表 → 一次路线 → 发现记录 |
| 伙伴对战 | 创建／加入 → 核对口令 → 双方确认 → 选卡 → 双方准备 → 回合操作 → 双方确认结果 |
| 设置 | 显示亮度、离线地图包、照片与存储、连接方式；管理观察时再次确认删除范围 |

## 4. 关键交互规则

### 识别与图鉴

1. 拍照后先看清晰度，再发起识别；返回不应丢掉刚拍的照片。
2. 候选先选中，再点“确认收藏”；来源与不确定性清楚呈现。预览中的候选顺序仅演示，不代表实际置信度。
3. 没认出来、联网不可用或用户不确定时，允许“先存照片”；待确认记录不解锁卡牌。
4. 保存提交成功才显示“已保存到本机”。重复发现追加观察，不无限叠加游戏数值。
5. 科普与游戏卡分开，卡牌明确标“游戏卡”。游戏数值和技能不作真实生物学描述。
6. 删除照片、删除观察、删除路线的影响不同；预览演示删除一条观察，并说明保留其他观察、物种与卡牌。

### 探索与地图

1. 离开地图去拍照、看图鉴时，探索继续，顶栏仍提示记录状态。
2. 区分当前有效位置、上次位置、尚无位置；未定位仍可拍照。定位中断不补画虚假连续轨迹。
3. 没有覆盖地图仍可记录有效坐标；“无地图”与“无定位”分别提示。
4. 暂停后不新增轨迹；结束前确认，提交成功后出现探索小结。重启恢复能力由后续存储设计保证。
5. 首版不提供路径规划和导航；缩放与回到位置使用显式按钮，不要求掌握双指手势。

### 双机对战

1. 设备名称配合短口令，双方确认后配对；不传输照片、轨迹或精确位置。
2. 先选卡、再准备。技能先选中、再确认出招；提交后禁用重复出招并显示等待伙伴。
3. 对方掉线时暂停；重连失败可结束未完成对局，不自动判胜。
4. 规则版本不同要明确解释并停止配对；正式胜负以双方同步确认的结算为准。
5. 设计预览会自动模拟识别和伙伴行动，便于试走流程；不是识别服务或通信协议实现。

## 5. 异常状态

| 状态 | 主提示 | 恢复路径 |
| --- | --- | --- |
| 未识别 | 暂时没认出来 | 重拍／先存照片 |
| 需要联网但不可用 | 现在连不上网络 | 重试／先存照片 |
| 定位未恢复 | 正在找位置 | 保留上次位置，继续拍照 |
| 地图无覆盖 | 走出地图范围了 | 继续记录有效位置 |
| 空图鉴 | 第一位自然朋友 | 拍照发现 |
| 空间满 | 这张照片尚未保存 | 管理空间／重试保存 |
| 存储介质缺失 | 暂时读不到记录 | 检查存储卡；不把记录当作已删除 |
| 伙伴未加入 | 还没有伙伴加入 | 保持靠近／取消 |
| 伙伴断开 | 对战已暂停 | 重连／结束未完成对局 |
| 规则版本不同 | 游戏版本不一样 | 返回，请大人协助更新 |

正式实现还需按相同视觉模式补上写入失败、未正常结束探索恢复、没有可出战卡片等业务状态；不以设计预览覆盖全部协议分支。

## 7. 审阅与实现边界

本次优先审阅：主推风格还是四宫格方案、字号与按钮大小、四个入口的优先级、拍照与对战操作步骤。名称、配色、文案和信息密度均可调整。

**用户已确认自然手帐，并授权首页和页面切换的实现、烧录。** 当前固件采用触摸输入与四点校准；是否需要实体按键仍待使用反馈。摄像头、GNSS、外部存储、识别方式和双机链路尚未完成验证，图鉴容量、地图性能和续航不作承诺。

落地时保持已验证的 LDO4 与硬件 SPI 点屏基础，采用局部刷新和有限图像缓存；中文字体、图片、地图、PSRAM 和任务内存预算在硬件验证后决定。预览的浏览器界面不是嵌入式固件代码。
