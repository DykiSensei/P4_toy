# P4 儿童自然探索玩具项目整体大纲

版本：v0.1 初稿  
更新日期：2026-11-09  
当前阶段：屏幕点亮完成；自然手帐首页、基础页面切换与触摸校准已通过用户实机确认，业务功能尚未接入

面向 6–12 岁儿童，制作一款可随身携带的自然探索玩具：通过摄像头识别身边物种，用 GPS 记录探索位置与路线，在离线地图上回看发现，将物种收入本机图鉴，再与另一台设备进行原创回合制对战。

开发先完成一套范围明确的可用原型，再扩展识别种类、地图范围和玩法。下文除“当前基础”中明确完成的项目外，均为规划；识别方式、外设型号、存储容量和续航指标需要通过实机验证确定。

2026-11-09 增量进度：用户选定“自然手帐”UI，已实现并烧录首页、四个功能入口、设置与返回，以及 XPT2046 四点触摸校准；用户确认均正常。业务入口仍明确显示待接入状态，M1 尚未整体完成。实现范围见 [UI 实现说明](ui/UI_IMPLEMENTATION.md)。

## 1 产品定位与首版范围

### 产品目标

- **自然观察**：鼓励孩子发现、拍摄和了解真实物种，通过拍照收集图鉴。
- **探索记录**：在本机保存路线、发现照片和位置，能够回看一次户外探索。
- **收集与游戏**：将已收集的物种转为游戏卡牌，用简单对战增加重复探索的动力。
- **便于使用**：以大图标、短文字、清晰反馈为主，适应 320×480 竖屏和户外操作。

### 首版建议范围

| 项目 | 首版目标 | 后续扩展 |
| --- | --- | --- |
| 物种识别 | 选定一类常见物种和一份明确的支持名单，验证真实识别 | 扩充物种、模型和识别环境 |
| 本机图鉴 | 照片、名称、简短知识、发现记录、可用对战卡 | 分类筛选、成就、更多科普内容 |
| 定位地图 | 一个预装区域、少量缩放级别、实时位置与历史轨迹 | 多区域地图包和更多展示方式 |
| 双机对战 | 附近两台设备配对，各选一张卡，进行回合制对战 | 多卡队伍、技能组合和养成 |
| 离线能力 | 地图、轨迹、已有图鉴和双机对战在无互联网时可用 | 扩展离线识别能力 |

物种识别是否要求完全离线，单独作为技术决策。首版不引入账号系统、公共排行榜、远程社交或物种交易；游戏成长不作为首版闭环的依赖。

## 3 核心使用流程与界面

一次典型使用流程：**开始探索 → 查看位置并记录路线 → 拍摄物种 → 查看识别候选 → 确认收入图鉴 → 回看发现地点 → 与伙伴配对对战**。

拍照和收藏也应能独立使用；GPS 暂时没有定位时，允许保存无位置的观察记录。

| 页面 | 主要内容与操作 |
| --- | --- |
| 首页 | 拍照识别、探索地图、我的图鉴、伙伴对战；显示电量和必要状态 |
| 拍照与识别 | 取景、拍照、重拍、识别进度、候选结果、确认收藏 |
| 我的图鉴 | 已收集物种列表、物种详情、发现照片、对战卡 |
| 探索地图 | 当前位置、轨迹、发现点；开始、暂停和结束记录 |
| 探索记录 | 历次路线、探索时间、当次发现和删除操作 |
| 伙伴对战 | 创建或加入、确认配对、选卡、回合操作、结果 |
| 设置 | 亮度、存储空间、地图包、连接配置和数据管理 |

页面应明确反馈“正在识别”“尚未定位”“地图未覆盖”“存储已满”“对方已断开”等状态。儿童界面使用易懂文字；连接参数、地图导入和批量数据管理放在设置中。

## 4 功能模块

### 4.1 摄像头与物种识别

完成取景、拍照、图像压缩、识别请求、结果显示和收藏确认。先选定识别场景与物种名单，例如从常见植物、昆虫或鸟类中选一类起步；名单外对象允许返回“暂时不认识”。

识别结果包含候选名称、识别来源和可用的可信度信息。可信度不足时提示重拍或保留为待确认记录，不自动生成已确认物种卡。用户可修正误识别；未能识别的照片可留待之后处理。

| 路线 | 实现方向 | 验证重点 |
| --- | --- | --- |
| 端侧识别 | 在设备上运行限定类别的模型 | 实际识别效果、模型大小、内存、耗时和耗电 |
| 联网识别 | 通过无线链路请求识别服务 | 户外联网条件、服务质量、请求耗时、成本和图片处理方式 |
| 混合识别 | 本地识别有限类别，按需联网补充 | 两种结果的统一映射、失败回退和使用复杂度 |

先用真实样本验证候选路线，再确定首版实现。保留统一识别接口，使界面、图鉴不依赖某一种模型或服务；联网路线不可用时，仍可拍照保存和浏览已有图鉴。

物种名称和科普信息来自受控目录，游戏数值由游戏规则配置；不直接把识别服务生成的文字当作对战规则。科普内容面向儿童审核，不将识别结果呈现为可食用或可触摸保证。

### 4.2 GPS 定位与轨迹

- 接入 GPS／GNSS 模块，获取经纬度、定位状态和可用时间信息；具体接口随模块选型确定。
- 支持开始、暂停、继续和结束一次探索，按时间或位移策略采样轨迹。
- 区分当前有效定位、最后一次有效定位和无定位；定位失效后不继续伪造新轨迹点。
- 对明显跳点和长时间定位中断进行处理，轨迹断段显示，避免把缺失路段画成实际经过的路线。
- 记录采用分段写入，意外重启后保留已提交的数据；未取得可靠时间时标记时间状态。

### 4.3 离线地图

GPS 提供位置，离线地图需要独立准备底图数据。首版预装一个明确区域，设备从本地读取地图，在其上叠加位置、轨迹和物种发现点。

- 地图包包含覆盖范围、缩放级别、坐标系、版本、来源和容量信息。
- 初期优先评估预生成栅格瓦片，验证空间占用、解码耗时与显示效果后再确定格式。
- 定位坐标和底图坐标必须匹配；在实地检查位置、轨迹和发现点是否正确重合。
- 超出覆盖范围或地图包损坏时明确提示；仍可继续记录有效定位和轨迹。
- 提供通过电脑导入、替换和删除地图包的维护流程，采用允许离线分发的地图来源并保留必要署名。

首版完成“看位置、看轨迹、看发现点”，暂不加入路线规划和转向导航。

### 4.4 本机数据库与图鉴

“本机数据库”指设备上可持久保存、查询和维护的数据集合，存储引擎在资源验证后确定，不预先绑定某一种数据库软件。

- 同一物种只保留一个物种目录条目，但可关联多次观察和多张照片。
- 首版建议每种已确认物种解锁一张对战卡，重复拍摄追加观察记录，不无限叠加战斗能力。
- 收藏后可浏览缩略图、名称、知识说明、发现时间及可选位置；断电重启后仍可访问。
- 区分删除照片、删除一次观察、移除收藏和删除探索记录，避免关联删除超出用户预期。
- 数据带格式版本；写入失败、空间不足或存储介质缺失时有明确反馈。

### 4.5 双机回合制对战

两台设备各从自己的本机图鉴选择已解锁卡牌，通过附近通信建立对局。首版采用一对一、固定基础数值和少量动作，先验证完整回合流程，再扩展队伍和成长系统。

- **配对**：创建或加入对局，双方确认配对信息，避免连错设备。
- **开局**：检查通信协议、物种目录和规则版本兼容性，交换参战卡的必要数据并固定本局快照。
- **回合**：选定一端作为本局裁决端，接收动作、检查合法性、计算结果并同步双方画面。
- **一致性**：消息包含对局号、回合号和消息序号，处理确认、重发、重复消息及超时。
- **结束**：双方确认相同结果后记录战绩；掉线时暂停、重连或结束，不自动生成相互矛盾的胜负。
- **交换范围**：只传输配对、参战和战斗数据，不交换完整数据库、照片或位置轨迹。

游戏属性和技能采用独立的原创规则，与真实物种知识分开呈现。对战传输方式在 C5 链路验证后确定，首版要求不依赖互联网。

## 5 硬件规划与资源约束

| 模块 | 计划职责 | 接入前需要确定 |
| --- | --- | --- |
| ESP32-P4 | 界面、图像处理、地图、数据管理和游戏逻辑 | RAM 预算、任务负载、外设资源分配 |
| ST7796S 屏幕 | 显示与交互反馈 | 局部刷新、图片显示耗时、背光控制 |
| 触摸或实体按键 | 拍照、选择、返回和地图操作 | 控制器、驱动、校准及户外操作体验 |
| 摄像头 | 预览和拍照 | 型号、接口、引脚、电源、镜头和驱动兼容性 |
| GPS／GNSS 模块 | 位置与时间 | 模块、接口、天线、安装位置和户外定位表现 |
| 外部存储 | 地图包、照片、轨迹与图鉴数据 | 优先评估 microSD；核对卡槽布线、容量与文件系统 |
| C5 无线部分 | 双机通信，以及可选的联网识别 | P4 与 C5 的连接、固件和通信方案 |
| 电池与电源管理 | 随身供电、充电、电量显示和休眠 | 峰值电流、供电稳定性、容量、发热和保护设计 |
| 外壳与装配 | 携带、镜头与天线固定、接口保护 | 握持、按键可达性、耐摔和维护方式 |

ESP32-P4 本身不内置 Wi-Fi 或蓝牙，无线功能需要外部无线芯片配合；本项目按 C5 路线验证。[ESP-IDF 官方说明](https://docs.espressif.com/projects/esp-idf/en/latest/esp32p4/get-started/index.html)

摄像头可优先评估官方 `esp_video` 与 `esp_cam_sensor` 组件。组件支持的芯片接口不等于当前开发板已接出或当前摄像头可直接使用，需核对板级连接、传感器驱动和 ESP-IDF 5.5.4 的版本兼容性。[官方摄像头框架说明](https://docs.espressif.com/projects/esp-video-components/en/latest/esp32p4/Get_Started/index.html)

已整理 [GPIO 分配表](GPIO_ASSIGNMENT.md)，包含供电域、排针脚号、现有占用和接口预留。屏幕及触摸接线占用 GPIO39–50，与固定 SD1 引脚 GPIO39–48 重叠；本版底板原理图未显示已接入的 SD 卡槽，外部存储需另行规划接口。保持已验证的 LDO4 供电逻辑，并保留 P4 与 C5 内部连接和摄像头控制资源。新增外设前按实物版本核对分配表。

不要仅凭“16MB Flash”规划全部地图、照片和模型；分别核算固件、模型、地图包、照片、轨迹及数据索引。摄像头预览和地图刷新优先使用有限缓存、较小预览窗口与局部刷新，帧率和容量在实测后确定。

## 7 数据组织

| 数据对象 | 主要内容 | 关系与约束 |
| --- | --- | --- |
| 物种目录 | 稳定物种 ID、名称、分类、科普文本、内容版本 | 与图片、观察和游戏数值分离 |
| 观察记录 | 记录 ID、照片引用、可选物种 ID、时间、可选位置、识别来源及确认状态 | 同一物种可有多条观察；未知物种也能留档 |
| 收藏与对战卡 | 物种 ID、解锁状态、卡牌配置引用 | 首版每物种一张卡；待确认观察不解锁卡牌 |
| 探索与轨迹 | 探索 ID、起止时间、分段轨迹、定位状态 | 观察可关联探索；中断路段保持断开 |
| 地图包 | 区域、坐标系、缩放范围、版本、瓦片索引、来源 | 与固件独立管理 |
| 对战会话与记录 | 对局 ID、规则版本、参战快照、回合状态和结果 | 与长期收藏数据隔离 |
| 设备设置 | 显示、连接、记录偏好和资源版本 | 小量配置独立保存 |

照片和地图采用文件存储，结构化记录保存引用与索引；最终文件格式、存储引擎和容量上限在存储实验后确定。定位和照片默认保存在本机；如启用联网识别，只发送所需图片，不默认附带轨迹或精确位置。

## 8 开发阶段与完成标准

以下为实施顺序，不代表已承诺工期。每阶段保留可运行版本与实机验证记录。

| 阶段 | 主要工作 | 完成标准 |
| --- | --- | --- |
| M0 屏幕基础 | 已有供电初始化、显示驱动、编译烧录和恢复资料 | 已完成屏幕色条与移动块实机验证；触摸和寄存器回读不计入完成范围 |
| M1 资源与交互验证 | GPIO 分配、PSRAM、存储、输入、基础页面；摄像头和 C5 最小实验 | 明确接口冲突处理方案；完成输入、存储读写、摄像头取帧及双设备收发验证，形成资源预算 |
| M2 识别与收藏闭环 | 摄像头页面、真实识别方案、结果确认、观察存储和图鉴 | 对选定物种完成真实拍摄、识别、确认、保存及重启回看；记录独立样本评估结果和失败情况 |
| M3 定位与地图闭环 | GNSS、轨迹、离线地图包及发现点关联 | 无互联网条件下完成一次真实户外路线记录，重启后可回看地图、轨迹和发现点 |
| M4 对战闭环 | 先实现单机规则，再接入双机配对、动作同步和异常处理 | 两台设备用各自收藏完成一局对战，结果一致；重复消息、超时及掉线有确定处理 |
| M5 整机整合 | 供电、电池、外壳、功耗管理、完整流程与使用体验 | 完成从探索到对战的整机演示，检查数据持久化、长时间运行、低电量和存储异常 |
| M6 内容与玩法扩展 | 扩充物种、地图、科普内容、队伍和成长系统 | 在首版资源和稳定性指标内逐项增加功能 |

M1 中尽早开展识别样本实验，避免完成其他模块后才发现模型或服务无法满足需求。M2 与 M3 的独立部分可并行，M4 的战斗规则也可先用测试卡开发；正式验收须接入真实收藏数据。

## 9 验证重点

- **显示与交互**：页面切换、触摸或按键响应、图片显示和地图操作耗时；户外可读性。
- **识别**：独立样本中的正确识别、错误识别、拒识、名单外输入表现，以及耗时和峰值内存；模拟返回结果只用于联调。
- **定位地图**：实地位置对齐、连续步行轨迹、失去定位后的状态、地图边界和重启回看。
- **存储**：照片与记录关联正确；断电或空间满时保护已提交数据。介质缺失时明确提示，停止相关写入，不误判数据已删除；重新接入后可恢复访问。
- **对战**：双方状态和胜负一致，重复动作不会重复结算，断线和版本不兼容可正常退出。
- **整机**：摄像头与无线工作时的供电稳定性、发热、运行内存、续航和充电使用体验。

识别准确率门槛、响应时间、目标续航、地图与照片容量应在 M1 形成首轮测量后冻结为验收指标。上述功能完成标准先用于推进原型，不把未测性能写成产品承诺。
